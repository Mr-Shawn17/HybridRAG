## 技术栈

## 项目背景

企业内部数据治理规范、指标口径定义与系统技术支持文档分散在大量 PDF 文档中（数据标准、治理流程规范、系统运维与故障处理手册等），业务与技术支持人员日常查找依赖人工翻阅，效率低、口径核对困难。团队基于 RAG 架构构建智能问答知识库：对 60+ 份治理规范与技术支持文档（覆盖 20 个业务域 × 3 个年度版本）进行结构化解析与切块，构建 **dense + sparse 双路召回 + RRF 融合 + 云端重排**的混合检索链路，接入大模型生成**带引用溯源**（业务域 / 版本 / 章节 / 页码）的答案，替代人工查阅。语料实测产出 **4 万+ 知识块**，其中表格类内容（指标口径表、元数据标准表）占比超过 **50%**，对文档解析质量与检索精度要求高。

## 项目职责

（团队 3 人分工：本人负责检索与索引核心链路，另两人分别负责数据获取与前端应用）

1. **设计并实现文档解析与切块管道**：基于 PyMuPDF 抽取正文 / 标题 / 表格三类内容块并记录章节层级，按块类型分治切块（SentenceSplitter 768/80；表格按行级切分且每段携带表头，避免单行被截断），自动注入 11 字段元数据（业务域、版本、章节、页码、块类型等），支撑元数据过滤检索与答案引用溯源；
2. **实现三路向量混合索引**：基于 Qdrant（Docker 服务端）为每个知识块同时建立三路向量表示——dense（BGE-M3，1024 维）、BM25 稀疏（jieba 分词 + tf 饱和与长度归一，IDF 由 Qdrant 服务端 Modifier.IDF 自动维护）、learned sparse（BGE-M3 同一次前向传播顺带产出，零额外编码成本），共入库 **40,609 个向量点**；
3. **实现端到端混合检索链路**：双路并行召回（各 Top 50）→ **RRF 融合**（k=60，客户端实现以保留分路归因能力）→ **bge-reranker-v2-m3 云端重排**（Top 25 → Top 5）→ Prompt 组装与引用溯源；完成纯向量 / 混合 / learned sparse / 元数据过滤**四组链路端到端实测**并通过；
4. **设计幂等增量入库机制**：point id 由知识块唯一标识派生 UUID5，保证重跑幂等；支持按业务域增量入库与整份文档替换；IDF 全局统计由向量库服务端维护，**新增/替换文档零全局重算**；
5. **低配 GPU 环境工程调优**：在 4GB 显存消费级 GPU 上实测定位 fp16 在无 Tensor Core 架构下反而**慢 4.7 倍**的问题，定版 fp32 编码；将编码结果缓存（npz）与入库流程解耦，调整元数据结构无需重跑 GPU 编码；定位并解决 Windows 平台 FlagEmbedding 原生 DLL 导入顺序导致的段错误（0xC0000005）；
6. **设计容错与降级链路**：embedding 本地 / 云 API 一键切换（同模型零迁移成本）、重排失败自动降级 RRF 排序并显式标记（防止静默降级污染评测结果）、评测流程对降级状态硬断言拦截；
7. **设计 LLM 评测体系（进行中）**：50 道分层合成测试题（术语精确 / 语义改写 / 数字提取三题型），RAGAS 四指标（ContextRecall / ContextPrecision / Faithfulness / AnswerRelevancy）+ 分层报告 + 最差题归因；评测裁判 LLM 与生成侧 LLM 异家族解耦，规避同族闭环偏置。
